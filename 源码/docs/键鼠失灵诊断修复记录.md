# 鼠标键盘失灵 诊断与修复完整记录

> 记录日期：2026-09-24 ｜ 系统：Windows 11 25H2（精简版）｜ 平台：AMD (9800X3D / X670 系芯片组)
> 状态：✅ 已修复并验证
> 用途：本记录可作为开发"键鼠/USB 失灵自动修复工具"的需求依据与算法参考

---

## 一、问题现象

- 鼠标、键盘（USB 有线/无线接收器）全部失灵，无法移动光标、无法输入。
- 系统其它功能正常，设备管理器中可见设备但均异常。

## 二、诊断过程与关键证据（按执行顺序）

### 2.1 设备状态快照（修复前）

`Get-PnpDevice -Class Keyboard,Mouse,USB` 输出摘要：

| 设备 | 修复前状态 | 问题码 |
|---|---|---|
| AMD USB 3.10 可扩展主机控制器 ×2 (DEV_15B7 / DEV_15B6) | Error | CM_PROB_DRIVER_FAILED_LOAD (39) |
| AMD USB 3.20 可扩展主机控制器 (DEV_43FC) | Error | CM_PROB_DRIVER_FAILED_LOAD (39) |
| AMD USB 2.0 可扩展主机控制器 (DEV_15B8) | Error | CM_PROB_DRIVER_FAILED_LOAD (39) |
| HID Keyboard / Mouse（真实键鼠 VID_373B、VID_3554） | Unknown | CM_PROB_PHANTOM（幽灵，因控制器失败未枚举） |
| HID\GVINPUT 虚拟键鼠 | OK | 正常（虚拟输入通道，与本次无关） |

> 注：CM_PROB_PHANTOM 表示设备此前插过、当前未枚举成功，属于**结果**而非原因；根因在 USB 主机控制器加载失败。

### 2.2 问题码精确定位

`pnputil /enum-devices /problem` 关键输出：

```
Device: AMD USB 3.10 可扩展主机控制器 - 1.20 (Microsoft)
Problem Code:  39 (0x27) [CM_PROB_DRIVER_FAILED_LOAD]
Problem Status: 0xC0000033
Driver Name:    usbxhci.inf
```

4 个 USB 控制器全部为 **问题码 39（驱动加载失败）**，状态 `0xC0000033`（STATUS_OBJECT_NAME_INVALID，对象名无效）。

### 2.3 驱动文件检查

`C:\Windows\System32\drivers\` 下 usbxhci.sys、usbd.sys、usbport.sys、usbhub3.sys、hidclass.sys、mouclass.sys、kbdclass.sys、wdf01000.sys 等 **全部存在且体积正常** → 排除"文件被精简删除"的可能。

### 2.4 注册表检查（★ 根因所在）

`HKLM\SYSTEM\CurrentControlSet\Services\usbxhci` 的 ImagePath：

```
损坏值：\SystemRoot\\SystemRoot\System32\drivers\USBXHCI.SYS   ← 多出 \SystemRoot\，路径无效
正常值：\SystemRoot\System32\drivers\usbxhci.sys
```

**根因结论**：USB 3.x 主控驱动服务 `usbxhci` 的 ImagePath 注册表值被写坏（出现连续两个 `\SystemRoot\`），驱动加载器按此路径找不到文件 → 返回 0xC0000033 → 驱动加载失败（0xC000026C）→ 4 个 AMD USB 控制器全部问题码 39 → 键鼠无法枚举。损坏格式高度疑似精简/优化工具批量改写注册表时产生。

### 2.5 事件日志佐证

`Microsoft-Windows-Kernel-PnP` 事件 ID **219**（驱动加载失败）：

```
驱动程序\Driver\USBXHCI加载失败。
Device： PCI\VEN_1022&DEV_15B8\...0043
状态： 0xC000026C   （STATUS_DRIVER_UNABLE_TO_LOAD）
```

## 三、修复操作（已执行成功）

| 步骤 | 操作 | 命令/说明 |
|---|---|---|
| 1 | 备份注册表键 | `reg export "HKLM\SYSTEM\CurrentControlSet\Services\usbxhci" backup_usbxhci_reg.reg /y` |
| 2 | 修正 ImagePath | `reg add "HKLM\SYSTEM\CurrentControlSet\Services\usbxhci" /v ImagePath /t REG_EXPAND_SZ /d "\SystemRoot\System32\drivers\usbxhci.sys" /f` |
| 3 | 重新扫描硬件 | `pnputil /scan-devices` |
| 4 | 重启 4 个 USB 控制器 | `pnputil /restart-device "<实例ID>"` ×4，均返回 "Device restarted successfully" |

> 修复期间 USB 会闪断数秒（控制器重启），属正常现象。

## 四、验证结果 ✅

1. 4 个 AMD USB 控制器状态由 `Error` → **全部 OK**
2. 真实键鼠（VID_373B、VID_3554 的键盘+鼠标）由 `Unknown` → **全部 OK**
3. 修复后 5 分钟内 Kernel-PnP 事件 219 新增数量 = **0**
4. 全注册表扫描 `SystemRoot\\SystemRoot` 双路径异常 = **0 处残留**

## 五、修复软件设计参考（开发者用）

### 5.1 检测模块（判定"键鼠/USB 失灵"）

按以下顺序检测，任一命中即进入修复流程：

1. **问题码扫描**：遍历 `Win32_PnPEntity`，标记 `ConfigManagerErrorCode = 39 (0x27)` 且 ClassName=USB 的设备。
   ```powershell
   Get-CimInstance Win32_PnPEntity | Where-Object {
       $_.ConfigManagerErrorCode -eq 39 -and $_.PNPDeviceID -like 'PCI\VEN_1022*'
   }
   ```
2. **注册表路径校验**：遍历 `HKLM\SYSTEM\CurrentControlSet\Services\*`，对每个 Type=1（内核驱动）服务校验 ImagePath 合法性，规则：
   - 含 `SystemRoot\\SystemRoot`（双 SystemRoot）→ 异常
   - 以 `\SystemRoot\` 开头但文件不存在 → 异常
   - 以 `System32\` 开头（合法简写）→ 正常
   - 指向 `\??\` 的第三方路径 → 不处理（白名单跳过）
3. **事件日志监测**：`Kernel-PnP` ID 219 / 411，状态码 `0xC0000033`、`0xC000026C`、`0xC0000034`(STATUS_OBJECT_NAME_NOT_FOUND)。
4. **键鼠存在性检查**：`Get-PnpDevice -Class Keyboard,Mouse` 中 HID\ 开头设备（非 GVINPUT 虚拟）状态是否 OK。

### 5.2 修复模块（自动修复流程）

```
[1] 管理员权限自检（无则请求提权）
[2] 备份受影响服务键 → 导出 .reg（时间戳命名，存 备份目录）
[3] 修正 ImagePath：统一写为 \SystemRoot\System32\drivers\<驱动名>.sys
    - 类型必须保持 REG_EXPAND_SZ（不能写成 REG_SZ）
[4] pnputil /scan-devices 重新扫描
[5] 对问题设备 pnputil /restart-device "<实例ID>" 逐个重启
    - 若 restart 失败 → 先 /disable-device 再 /enable-device
[6] 复检：设备状态 + 事件日志增量，输出成功/失败报告
```

|---|---|---|
| usbxhci | usbxhci.sys | USB 3.x 可扩展主机控制器（xHCI） |
| usbehci | usbehci.sys | USB 2.0 EHCI 控制器 |
| usbohci | usbohci.sys | USB 1.1 OHCI 控制器 |
| usbhub3 | usbhub3.sys | USB 3.0 根集线器 |

### 5.4 错误码速查表（软件内置文案）

| 值 | 含义 | 指向 |
|---|---|---|
| 问题码 39 (CM_PROB_DRIVER_FAILED_LOAD) | 驱动加载失败 | 注册表 ImagePath 损坏 / 文件缺失 / 签名问题 |
| 问题码 28 (CM_PROB_FAILED_INSTALL) | 驱动未安装 | 缺驱动 / INF 问题 |
| 问题码 10 (CM_PROB_START_FAILED) | 设备无法启动 | 硬件故障 / 资源冲突 |
| 问题码 22 (CM_PROB_DISABLED) | 被禁用 | 手动禁用（勿自动启用，记录即可） |
| 0xC0000033 | 对象名无效 | **ImagePath 指向错误** |
| 0xC000026C | 无法加载驱动 | 驱动加载失败（伴随 39） |
| 0xC0000034 | 对象名未找到 | 驱动文件缺失 |

### 5.5 软件健壮性建议

1. **只修白名单驱动服务**（上表 + 微软内置驱动），第三方 `\??\` 路径一律跳过，防止误伤反作弊/硬件工具驱动。
2. 修改前**必做 reg 导出备份**，且提供"一键回滚"（导入备份 + 重启设备）。
3. 修复后必须**复检**（不能只报"已执行"）：状态 OK + 日志无新增 219。
4. 区分"幽灵设备"(CM_PROB_PHANTOM) 与真实故障——PHANTOM 是残留记录，不是问题，**不要**据此报故障。
5. 电源管理项（USB 选择性暂停）可列为预防性建议，但本次故障**与它无关**，不要用它干扰诊断。
6. 需管理员权限运行；界面建议提供：一键诊断 → 结果列表 → 一键修复 → 复检报告。
